# 系统框架工作法（教学材料，不是完整系统的代替品）

明确模块接口、状态转换、资源所有权与失败传播；用最小可运行切片验证这些契约。
覆盖 acquire 失败、body 失败、正常释放、重复释放、move 转移与 moved-from 状态。
取消、重试、超时、排队、背压、关闭过程不能仅检查 happy path。
状态机深度和场景预算必须公开，浅层检查不能宣称穷尽并发 interleaving。
任务从初始化、执行、停止到清理的每步都需要可观察证据，避免对象自报状态代替外部计数。
推理系统分开验证权重布局、单层数值、全层数值、prefill/decode、KV cache 与端到端输出。
复杂系统应由可独立编译和验收的模块组成；模型规模小不意味着可以省略接口和证据。
单算子加速不能推导引擎吞吐；调度、同步、cache、内存与请求负载都要独立测量。
