# 架构与扩展

## 数据流

新任务入口 `task_solver.py` 先用 `SolvePolicy` 和原任务合同选择已有模块，再调用 `create_runtime` 或 `create_cpu_request`；CLI 由 `solve_cli.py` 转接。它不创建第二个模型循环。选择及执行摘要写入 `capabilities.json`，不将“装配成功”当成“已经送达模型”或“任务成功”。

```text
TaskSpec + ModelConfig + RuntimeConfig
  → 合同校验 / 会话锁 / 累计预算
  → 领域路由 / 代码分析与检索 / 工作计划
  → 模型提出动作 → 权限与版本校验 → 修改或观察
  → 公开诊断反馈 → 局部修复
  → 冻结快照上的独立最终验收 → 状态与事件
```

公开配置位于 `config.py`，用户入口为 `cli.py`。`engine.py` 保留现有调度；`agent_execution.py` 负责已有 Runtime/Native 分派。该预览版没有重写全部内部接口，避免在发布整理时改变已验证路径。

`runtime_checks.py` 将已有 CPU 沙箱与脚本验收器接到 Runtime 的公开 verifier。模型只收到公共失败信息；独立 final 不进入 Runtime 的修复循环。它不授予模型命令权限，执行前后复核非授权源码身份。旧 TaskSpec 检查和新脚本配方显式互斥，避免同一个“成功”同时代表不同验收合同。

此图描述普通 Runtime 的主要机制，不表示所有阶段必经，也不表示所有高级模块默认接通。各入口的实际启用条件见[当前能力与启用状态](capabilities.md)。

## 代码与记忆

`code_context.py` 和 `languages/` 建立 SQLite 索引，`repository_memory.py`、`long_memory.py`、相关工作集模块按仓库、模块和符号组织上下文。文件哈希、分析器身份和源位置用于失效检查，任务经验与源码事实不应混为一谈。

普通 Runtime 默认启用的是版本化代码记忆。Native 的压力触发任务工作记忆另有开关，默认关闭；跨任务 `ExperienceBank` 也需要调用方提供，默认没有全局经验积累。

Python 使用 AST、作用域和静态数据流候选；C/C++/CUDA 可通过编译数据库与 Clang 提供更精确信息。动态调用、复杂别名、未实例化模板和不完整构建环境会留下未知关系。启发式匹配不能升级为语义解析证据。长代码理解效果须通过真实任务和上下文成本验证。

## 规划与领域流程

计划含目标、依赖、读写范围、接口和检查步骤。运行时校验计划，不允许规划改写最终验收。基础路由依据修改范围等条件决定是否要求计划；调用方也可提供里程碑。grounded planning、自适应重规划等增强需显式开启，不能把阶段执行支持等同于默认自主重规划。

`profiles.py` 负责领域分类，Native `cpu-auto` 使用既有能力管线；`solve` 调用这些现有选择器，不复制另一套复杂度判断。`capability_router.py` 的高级模块标签实验继续通过 `infinicoder-adaptive` 显式访问。`workflows/`、`knowledge/`、`domains/` 提供流程与知识：算子关注数学语义、布局、精度和边界，框架关注状态、所有权、调度和同步不变量。独立性能测量及候选保留/回退仍需调用方绑定优化目标、环境和测量策略。

模板、知识卡和种子仅提供建议。种子前置条件、修改后的正确性与真实性能均需重新验证。

## 多角色与实验边界

`collaboration*` 提供显式调用的单分支、同构与异构策略。异构路径可先生成策略建议，再运行独立副本中的实现分支，由父级按公开结果选择并最终验收；共享预算和执行环境由调用方绑定。普通 Runtime 的 `automatic_workers` 不会调用此协调器。Native 的假设分支是另一条受限候选搜索路径，不等同于通用多角色讨论。

`advanced` 暴露调用方适配器、领域 provider 和历史实验，便于扩展，而不把全部组合放入默认推荐配置。新增能力应明确输入、权限、预算、产物、验证和退回条件，复用现有路由与执行器。

## 维护方向

当前 engine 仍较大，高级选项较多。下一步按会话生命周期、上下文组装、动作分派和验收协调拆分内部职责，保留单一预算/权限/验收来源；先通过接口行为测试，再迁移实现。不要同时改调度、记忆策略和评测裁判来解释收益。

能力迭代使用固定小型多领域 benchmark，先做匹配预算的开发实验，再冻结候选和保留集；只有独立任务上可复现的收益才成为推荐策略。失败和停止假说保留在独立研究档案，不进入用户默认流程。

## 模型调用

Runtime 的 `CompatibleClient` 和 Native 的 `InfiniLMTextModel` 使用 HTTP 聊天接口。Native 保留物理调用账本、真实 tokenizer 预算、任务截止和独立验收；普通请求不会自动重试未知结果。仅交付策略证明请求尚未发送时，允许一次重试。调用层不加载模型权重，也不依赖 LiteLLM 或外部 mini-SWE SDK。

Native 的文本协议组件包含必要的 MIT 授权衍生代码，原始署名与修改说明见根目录 `THIRD_PARTY_NOTICES`。独立对照智能体、基准测试集与实验输出不随产品分发。
